# 公共接口清单与实现约定（v1）

本文件和 `include/` 中的头文件共同定义全组的公共接口。目标是让五名成员按相同的数据结构、函数签名和业务规则开发。

**main 基线的实现状态：** 12 个公共头文件已发布，`src/result.c` 中的 `result_message` 已实现。其余函数（包括 `app.h`、`sales.h` 的声明）尚无实现合入此基线，业务实现通过各成员 PR 补齐。当前不能仅包含头文件就调用并链接这些待实现函数。不要编写“总是返回成功”的占位实现。

这些是小组的设计选择：单进程控制台程序、单一币种、每个披萨各选一种饼底/尺寸/口味、整数分计价、单个完整状态文件。题目没有强制这些实现细节。多配料、退款、并发、多经理账户和真实支付均不属于 v1 接口。

## 2. 全组必须遵守的公共规则

### 类型与数据

- `AccountId`、`OrderId`、`MenuOptionId` 均为 `uint64_t`；有效记录编号非零，按各自计数器递增，停用后不复用。菜单编号跨饼底、尺寸和口味三个类别唯一。
- `Money` 是 `int64_t`，单位为分，例如 `3250` 表示 32.50。价格和余额非负，充值金额必须大于零；零元订单允许。每一步加法、乘法和计数器递增都须检查溢出。
- 固定字符串必须有 NUL 结尾；名称和登录名最多 63 字节，电话最多 31 字节，均不得为空或包含控制字符。名称、电话使用 UTF-8，容量按字节计算，不按汉字数量计算；不得静默截断。
- 注册、首次经理设置的密码长 8～64 字节，不含控制字符，不自动去除空格。登录须使用相同原文验证；验证失败统一返回 `RESULT_AUTH_FAILED`。密码只作为调用期间借用的输入，公开客户数据不包含密码，也不向日志、销售快照或错误文本输出密码。私有验证记录由账户与存储实现维护，接口声明本身不代表已完成凭据保护。
- `Timestamp` 为 UTC Unix 秒，创建订单时由程序获取；显示时才转换到本地时间。
- 每单 1～20 条明细，每条数量 1～99。相同配置可出现在多条明细中，不强制合并。超出条数/数量上限返回 `RESULT_CAPACITY_EXCEEDED`；零条明细、零数量等不合法值返回 `RESULT_INVALID_INPUT`。
- `Customer`、`MenuOption`、`Order`、报价等输出都是独立的值副本；修改副本不会修改系统。`AppState` 故意使用不透明类型：集合、凭据、路径和计数器由内部实现管理，其他模块不自行访问其布局。

### 参数、返回值与所有权

- 除明确允许为 NULL 的参数外，指针必须非空；调用参数结构错误返回 `RESULT_INVALID_ARGUMENT`。有效参数中的非法业务输入返回 `RESULT_INVALID_INPUT`。
- 输出对象不能与输入对象重叠。除下述例外外，失败时输出参数和系统状态不变。
- 输入字符串、会话、草稿和输入流均为借用；函数不能释放、关闭或保留它们。除非另有说明，函数不会把输出指向内部可变数组。
- 登录在检查参数前先清空非空的 `out_session`；任何失败都不得留下上次的登录身份。`account_logout` 清零会话，允许传 NULL。
- `input_read_line` 失败时清空合法缓冲区，并尽可能消费当前行；无法恢复的流错误直接返回 `RESULT_IO_ERROR`。
- `storage_open/create` 要求传入的 `*out_state == NULL`，成功后由调用者拥有；仅通过 `storage_close` 释放。失败不能把半加载状态交给调用者。
- `SalesSnapshot` 先初始化为 `{0}`，仅通过 `order_sales_snapshot_free` 释放。成功后快照独立于 `AppState`，释放状态对象后仍可读取快照；释放快照后清零，可再次使用。
- 状态对象绑定一个数据文件；同一个文件只由一个进程、一个状态对象访问，所有调用串行执行。内部事务和读写不需要支持并发调用。

### 列表统一约定

所有 `*_list*` 接口使用 `out_items + capacity + out_count`，避免各模块使用不同的内存管理方式。

1. 先以 `out_items=NULL, capacity=0` 查询所需条数，成功返回 `RESULT_OK` 并设置 `*out_count`。空列表也是成功。
2. 调用者申请足够的数组，再次调用复制记录；成功时设置实际条数。账户和菜单按编号升序，历史按订单号降序。
3. 若数组容量不足，返回 `RESULT_BUFFER_TOO_SMALL`，将 `*out_count` 设为所需条数，数组不写入部分记录。
4. `out_count` 必须非空；`out_items=NULL` 且 `capacity>0` 为非法参数。其他失败不修改数组或条数，尤其不能通过未授权的列表查询泄漏记录数。
5. 数组由调用者分配和释放。记录中没有需要另行释放的内部指针；分配前检查 `count * sizeof(record)` 是否溢出。

### 权限

- `Session` 只能由登录接口产生；适配器不能仅根据用户选择“客户/经理”就填写角色。
- 客户会话的 `account_id` 非零，经理会话的 `account_id` 为零。未登录或角色不符返回 `RESULT_PERMISSION_DENIED`。
- 客户业务每次重新检查账户仍然存在且启用；停用账户返回 `RESULT_ACCOUNT_INACTIVE`，包括登录成功后被停用的情况。
- 客户可读取和编辑自己的资料、查询自己的余额和订单；经理可管理所有客户及菜单、查看销售快照。跨客户访问返回 `RESULT_PERMISSION_DENIED`，不返回对方数据。
- 客户自行充值；经理修改客户资料的接口不能直接改变余额、编号或认证信息。
- 会话只在产生它的状态对象生命周期内使用，关闭状态后失效。公开结构是进程内部协作约定，不是可接受任意外部身份数据的接口。

### 保存与结算

- 注册、资料修改、客户停用/启用、菜单修改、充值、下单：成功返回前必须完成持久化。
- 由存储内部提供统一事务机制：构建候选状态，写完整临时文件，检查写入/刷新/关闭结果，再用可保留旧文件的替换方式提交，最后发布内存新状态。
- 任一步失败，返回 `RESULT_IO_ERROR` 等错误，保留旧状态和旧文件。禁止先删除旧文件再尝试替换；也不能先扣款再单独追加订单。进程或系统崩溃后的恢复还需由存储实现单独验证。
- `order_submit` 一次提交订单、余额、下个订单号；仅该接口协调结算。`wallet_calculate_debit` 只做算术，不保存独立扣款。
- 内部候选状态、提交和序列化辅助函数由成员 3/4/5 协作实现，放在私有头文件中，不作为可绕过业务规则的公共写入口。`storage_close` 只释放资源，不承担延迟保存。
- 不直接用 `fwrite(&object, sizeof(object), 1, file)` 持久化公共结构：其中含有 `size_t`、布尔值、填充和私有状态。存储层自行编码版本化字段，并校验记录长度、关联和总金额。

## 3. 接口清单

下表中的函数签名已完整声明在对应头文件中。

### 公共与存储

| 函数 | 用途 / 关键输出 |
| --- | --- |
| `result_message` | `Result` 转静态说明文本；未知值也返回非空说明 |
| `storage_open` | 加载已有数据文件并返回独占拥有的 `AppState *` |
| `storage_create` | 首次创建文件，显式设置经理凭据；已有路径返回 `ALREADY_EXISTS` |
| `storage_validate` | 只读校验当前状态，包括编号、引用、金额和历史明细 |
| `storage_close` | 释放状态；允许 NULL；调用者随后置空自身指针 |
| `input_read_line` | 读取完整一行，无提示输出；EOF 与非法输入分别返回 |
| `input_parse_u64` | 解析给定范围内的无符号十进制整数 |
| `input_parse_money` | 严格解析非负金额，例如 `12.3` 转为 `1230` 分 |

新建状态：菜单为空、客户和订单为空、三个编号计数器从 1 开始、菜单版本为 1。父目录须已存在；没有内置经理密码。用户名使用 `PIZZA_LOGIN_CAPACITY` 的长度规则。

`storage_open` 不存在文件时返回 `NOT_FOUND`；格式损坏、版本不支持、重复或零编号、悬空客户/菜单引用、错误金额和计数器异常返回 `INVALID_DATA`；权限等读取失败返回 `IO_ERROR`。禁止把损坏文件当成空文件覆盖。初始菜单由经理通过菜单接口添加。

### 账户（成员 1）

| 函数 | 谁能调用 | 行为 |
| --- | --- | --- |
| `account_register` | 未登录用户 | 创建启用客户，初始余额 0，返回新账户号 |
| `account_login_customer` | 未登录用户 | 账户号＋密码登录，输出客户会话 |
| `account_login_manager` | 未登录用户 | 经理用户名＋密码登录，输出经理会话 |
| `account_logout` | 当前界面 | 清空会话 |
| `account_get_customer` | 本人 / 经理 | 复制公开客户资料和余额 |
| `account_update_profile` | 本人 / 经理 | 只修改姓名和电话 |
| `account_add_customer` | 经理 | 与注册相同的初始化规则，但必须验证经理权限 |
| `account_set_active` | 经理 | 停用/恢复客户，不清余额，不删除历史 |
| `account_list_customers` | 经理 | 列出客户，可选择包含停用记录 |

电话不是登录标识，不要求唯一；身份由唯一账户号区分。自助注册与经理新增共用内部创建逻辑，不能各自维护编号计数器。

### 菜单与计价（成员 2）

| 函数 | 谁能调用 | 行为 |
| --- | --- | --- |
| `menu_get` | 所有人 | 根据编号获取选项，包括已下架选项 |
| `menu_list` | 所有人 | 按 `MENU_CRUST/SIZE/TOPPING` 列出选项 |
| `menu_get_revision` | 所有人 | 获取当前菜单版本 |
| `menu_add` | 经理 | 新增选项、分配全局菜单编号、默认上架 |
| `menu_update` | 经理 | 修改名称和价格，不改变编号或类别 |
| `menu_set_available` | 经理 | 上架/下架，保留历史关联 |
| `pricing_quote` | 所有人 | 校验配置、计算单价和小计，返回菜单版本 |

v1 将 `Supreme/Hawaiian/Margherita/BBQ Chicken` 等视为口味方案，映射为 `MENU_TOPPING`。每个披萨各选一个饼底、一个尺寸、一个口味。价格公式固定为：

```text
单价 = 饼底基础价 + 尺寸加价 + 口味加价
明细小计 = 单价 × 数量
订单总额 = 所有明细小计之和
```

编号不存在返回 `NOT_FOUND`；编号所属类别错误返回 `INVALID_INPUT`；选项已下架返回 `OPTION_UNAVAILABLE`。每次成功的菜单写操作递增菜单版本，即使更新值与原值相同；版本溢出则整次操作失败。菜单更名、改价、下架不修改历史订单。

### 余额与历史（成员 4）

| 函数 | 谁能调用 | 行为 |
| --- | --- | --- |
| `wallet_get_balance` | 当前客户 | 返回本人余额 |
| `wallet_check_funds` | 当前客户 | 非负金额的余额检查；不扣款，不保证后续结算成功 |
| `wallet_deposit` | 当前客户 | 充值正金额，保存成功后返回新余额 |
| `wallet_calculate_debit` | 订单实现 | 纯函数：余额－非负金额；不足返回 `INSUFFICIENT_FUNDS` |
| `history_list_orders` | 当前客户 | 按当前会话筛选历史，不接收任意客户号 |

查询某一历史订单的详情使用 `order_get`。客户停用不删除其余额和历史；经理仍能查询、编辑资料或恢复客户。

### 订单与销售快照（成员 3）

| 函数 | 谁能调用 | 行为 |
| --- | --- | --- |
| `order_quote` | 所有人 | 对草稿统一报价，填充成交候选名称/价格，不分配订单号 |
| `order_submit` | 当前客户 | 对已确认报价重新校验，原子扣款并创建已支付订单 |
| `order_get` | 本人 / 经理 | 按订单号复制订单，客户仅能读取本人订单 |
| `order_export_sales` | 经理 | 分配完整销售快照，供现有统计模块读取 |
| `order_sales_snapshot_free` | 快照拥有者 | 释放快照及全部明细并清零；允许 NULL/空快照 |

结算顺序：验证客户 → 检查草稿和明细上限 → 重算配置和报价 → 验证客户确认内容 → 检查余额 → 创建候选订单 → 一次持久化 → 更新内存 → 返回订单号。

`order_submit` 不信任传入的 `confirmed_quote`，必须按当前菜单重算，并比较菜单版本、有效明细数量、配置、历史名称、数量、单价、小计和总额。菜单版本变化或报价与草稿不一致返回 `QUOTE_CHANGED`，要求界面重新报价和确认；无效配置、下架、数量和余额错误返回对应业务错误。名称快照由当前权威菜单产生并核对，不接受调用者伪造的历史名称。

相同草稿提交两次视为两次购买；本接口没有重试令牌。界面只在客户确认后调用一次，成功后清空已提交草稿。取消未提交草稿不扣款、不分配订单号、不创建历史。

历史明细保留饼底/尺寸/口味编号、名称、单价、数量和小计；订单总额等于明细小计之和。v1 无优惠，故小计等于成交单价乘数量。统计沿用已有口径：

- `SalesLine.pizza_id = OrderLine.config.topping_id`，即按稳定的口味编号汇总，跨饼底/尺寸合并；不会把同一口味改名前后分成两类。
- `pizza_name` 使用历史 `topping_name`；名称容量与现有统计接口相同，均为 64 字节。
- `quantity` 使用明细数量；`revenue_cents` 使用**已含数量的历史小计**，统计时不能再乘一次数量。
- 显式把 `ORDER_*` 映射为 `SALES_*`，不依赖两个枚举数值恰好相同。只有 `SALES_PAID` 参与统计；其他状态仅预留，本版不提供退款和取消已支付订单的接口。
- 导出的快照必须完整，不分页、不返回部分成功；分配失败由导出函数清理临时资源，保持输出不变。

## 4. 与已有 AppServices 对接

保留现有 `AppServices`、`AppSession` 和 `SalesResult`，不改现有回调签名。新业务 `Session` 含角色信息，旧 `AppSession` 只传客户编号；适配器的私有上下文保存 `AppState *` 和真实业务会话。

| 现有回调 | 适配到的新接口 |
| --- | --- |
| `register_customer` | 读取资料和密码 → `account_register` |
| `login_customer` | 清除上下文旧会话 → `account_login_customer` → 成功时填写 `AppSession.account_id` |
| `login_manager` | 清除上下文旧会话 → `account_login_manager` |
| `edit_profile` | `account_get_customer` → 读取新资料 → `account_update_profile` |
| `manage_customers` | `account_list_customers`、`account_get_customer`、`account_add_customer`、`account_update_profile`、`account_set_active` |
| `manage_menu` | `menu_list`、`menu_get`、`menu_add`、`menu_update`、`menu_set_available`，含价格管理 |
| `show_balance` | `wallet_get_balance` |
| `deposit` | 解析正金额 → `wallet_deposit` |
| `place_order` | `menu_list` → 构造草稿 → `order_quote` → 展示确认 → `order_submit` |
| `order_history` | `history_list_orders` → `order_get` |
| `load_orders` | 验证上下文经理会话 → `order_export_sales`，保留快照至配对释放 |
| `release_orders` | 验证为当前借出快照 → `order_sales_snapshot_free` |

适配器检查传入的 `AppSession.account_id` 与上下文客户会话匹配。每次登录尝试先清空旧会话，不能沿用上次客户或经理身份；程序退出时也清理上下文会话。现有菜单没有独立注销回调，若以后需要精确的会话注销通知，再扩展菜单接入层。

快照适配器不能提前释放或在释放前重复覆盖快照。失败时将 `Result` 转为现有回调的非零返回值，错误说明可使用 `result_message`；不能把 `Result` 当成 `SalesResult` 强制转换。只有 `RESULT_OK` 映射为回调成功的 `0`。

## 5. 实现与验收顺序

1. 成员 5 与成员 1/3/4 完成私有状态、凭据保存、候选状态提交和加载校验。
2. 各成员实现对应 `.c`，函数签名严格使用头文件；将已完成源文件加入 `CMakeLists.txt`。
