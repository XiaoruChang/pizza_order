## 问题与需求分析

本项目为门店终端披萨点餐系统，采用 C 语言模块化开发。第五部分依据分工完成经理销售
统计和整体程序菜单，使客户业务与经理业务可从统一入口进入。

需求细化如下：

1. 经理登录成功后查看已支付订单数、披萨销量和销售额，并按披萨显示明细汇总。
2. 销量按披萨数量计算，不能用订单数替代；销售额按下单时实收金额计算，不能使用现价。
3. 未支付、取消和退款订单不计入统计；无已支付订单时清楚显示零值。
4. 客户菜单提供点餐、余额查询、充值、历史和资料入口；经理菜单提供菜单/价格管理、
   客户管理及统计入口。各业务交给对应成员模块。
5. 无效输入不得误触发业务；缺少模块、登录失败或统计数据损坏时应报告原因。
6. 统计为只读操作，不能重复扣款、保存订单或修改源数据。

实现开始时远程 `main` 仅有初始 README，没有公共结构或成员模块。因此本次能实现
统计、菜单分发和独立接入样例，真实业务联调仍依赖其他成员代码。

## 程序设计

`main` 负责绑定 `AppServices`，`app_run` 驱动主菜单。账户模块成功返回客户会话后
进入客户菜单；经理认证成功后进入经理菜单。未提供认证回调就拒绝进入对应菜单。
每次客户登录创建新的空会话，防止上一位客户的账户号残留。

经理请求统计时，菜单执行“加载一致快照→构建报告→释放快照→显示报告→释放报告”。
快照加载失败与空订单严格区分；统计失败不输出部分汇总。回调和数据生命周期详见
`integration.md`，其他成员可通过适配器保留原有内部数据结构。

`SalesOrder` 含订单编号、状态、明细指针和数量；`SalesLine` 含披萨编号、历史名称、
数量及实际实收小计。金额采用 `int64_t` 整数分，数量采用 `uint64_t`，避免浮点累计误差。
输入中所有明细必须使用同一币种，最多两个小数位。

统计首先检查已支付订单编号是否重复及容量是否溢出，然后逐条校验并按披萨编号累加。
同一披萨不同尺寸/配料的销量在稳定披萨 ID 下合计，金额已经包含尺寸/配料费用。
重复 ID 保留首次历史名称，最后按 ID 升序输出。没有接入现价表，不会因改价影响历史销售。
结果独立持有名称及汇总值，不依赖源快照继续存活。

为保持课程项目可读性，使用线性查找聚合：设订单数为 N，已支付明细数为 L、披萨种类数
为 P，时间复杂度为 O(N² + L×P + P log P)，额外空间 O(L)。适用于当前单店课程样例；
若后续数据量增长，可在不修改公共 API 的情况下优化索引。

菜单采用循环而非递归。通过完整行读取、数值范围校验和超长行清空防止输入串扰。
终端文本采用 ASCII 英文，便于现有 Windows MinGW 控制台运行；本说明和 PR 为中文。

## 实际测试记录

执行日期：2026-11-27。环境：Windows、MinGW-w64 GCC 8.1.0、CMake 4.4.0-rc1，
Debug/C11，开启 `-Wall -Wextra -Wpedantic -Werror`。旧版 MinGW 的 `printf` 长整型
兼容性通过 `__USE_MINGW_ANSI_STDIO=1` 处理，保持严格警告检查。

实际执行：

```powershell
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

构建成功，CTest **3/3 通过**。其中统计包含 5 组场景，菜单集成包含 6 组场景，
冒烟测试实际运行正式入口和独立演示两个可执行文件。测试使用失败即退出的检查宏，
不依赖可能被 Release 模式关闭的 `assert`。

| 测试 | 输入/操作 | 预期与实际结果 |
| --- | --- | --- |
| 已支付统计 | 多订单、多披萨、重复披萨、更名、不同历史价格 | 2 单、6 个、151.51；ID 升序，按实收累计，通过 |
| 状态过滤 | 未支付、取消、退款混入样例 | 都不计入；非支付订单的无效明细指针不读取，通过 |
| 空数据 | 空快照或全部未支付 | 0 单、0 个、0.00，显示无已支付订单，通过 |
| 非法订单 | 空指针、无明细、重复订单 ID、未知状态、ID 为 0 | 拒绝快照且输出报告保持空，通过 |
| 非法明细 | 数量为 0、负金额、空名称、控制字符、未结束名称 | 拒绝且不输出部分结果，通过 |
| 数值边界 | 最大数量/金额，累计再加 1，容量溢出 | 最大值可统计并正确打印，超限返回错误，通过 |
| 历史/内存 | 构建后修改源名称，赠品金额为 0，重复释放 | 报告保留历史名称；赠品有销量；重复释放安全，通过 |
| 功能路由 | 注册、客户 5 项、经理 3 项逐项选择 | 对应回调次数及账户号匹配，通过 |
| 身份与隔离 | 登录失败、账户号为 0、再次登录不返回 ID、客户选择 3 | 拒绝无效会话；客户 3 只调用充值，不调用统计，通过 |
| 模块缺失 | 无认证、业务回调为空、只有加载无释放 | 明确提示；不绕过认证或加载无法释放的快照，通过 |

| 菜单健壮性 | 文字、数字后接文字、负数、越界、空行、长数字、超长行、EOF | 不误触发业务；完整消费超长行；EOF 退出，通过 |
| 失败传播 | 业务回调失败、不可写输出流、非法 app_run 参数 | 显示失败或返回错误，无死循环，通过 |
